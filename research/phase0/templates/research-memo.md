# Phase 0 research memo — or-signals

This memo is generated by `research/phase0/render_docs.py` from harness
`results.json` files. Narrative is the template; every quantitative claim is
substituted from those files. Re-run `make research` after changing a harness.

**Safety.** This project is research, not a clinical monitor and not a
medical device. Depth-index proxies (BIS-like traces) are not awareness
labels. Label-proxy limitations are stated up front. No patient-identifiable
data is committed. Sample waveforms are synthetic.

---

## §1 Problem statement

Anesthesia teams watch arterial lines, pulse oximeters, infusion pumps, and
a processed EEG index. Two failure modes sit at opposite ends of the same
dial: the patient is too light (intraoperative awareness) or too deep
(over-sedation, hemodynamic collapse). Raw infusion rate is a poor stand-in
for how much drug is at the effect site after a bolus. An arterial flush
looks like a blood-pressure catastrophe if a model has no quality module.

The people who pay are patients who wake, patients who are over-narcotized,
and hospitals that inherit a monitor alarm they cannot audit. The obvious
fix — "train a network on VitalDB BIS" — ignores that awareness labels are
almost absent, that BIS is a proxy, and that flush artifacts will be learned
as hypotension.

This repo is waveform-first. Artifact/SQI is a first-class module. Exposure
is effect-site concentration from a published PK/PD model, not the pump
rate. Phase 0 exists to measure whether enough labels exist to attempt
awareness at all.

## §2 Prior art

| Tool | What it does | Gap |
| --- | --- | --- |
| [VitalDB](https://vitaldb.net/) / [PhysioNet mirror](https://www.physionet.org/content/vitaldb/1.0.0/) | ~6,000 high-fidelity OR cases | A corpus, not a quality+PK/PD pipeline |
| Commercial BIS / entropy monitors | Processed EEG index | Closed; not an awareness label |
| Target-controlled infusion (Schnider/Marsh/Minto) | Published PK/PD | Pump feature, not a research trail with SQI |
| [NeuroKit2](https://neuropsychology.github.io/NeuroKit/) / WFDB | Waveform I/O and SQI fragments | Not OR-specific; no effect-site layer |
| Anesthesia information systems | Infusion rates and vitals | Rarely store waveforms with a typed quality object |

TCI pumps already compute Ce. Another tool is still worth building because
the failure is the join: quality-gated waveforms + Ce + an honest statement
about which label you actually have. The product is that join, not a new
BIS.

## §5 Evaluation design

Hold-out (Phase 3): a pinned list of VitalDB case ids after a license
decision, if redistribution or local bronze storage is allowed. Until then
the synthetic five + 200-row index are the only labeled objects.

Metrics, declared before any model is built:

- Per-signal usable fraction after SQI
- Flush rejected and not called hypotension
- Dropout gaps reported, zero interpolation
- Label rates: awareness vs usable depth
- corr(Ce, depth-proxy) vs corr(rate, depth-proxy) on bolus
- Baseline: raw infusion rate, no SQI
- Phase 3: over-sedation event detection vs that baseline

Split: committed files. Seed 0.

**Failure condition (written before the answer):** the project fails if the
quality module labels a designed flush window as hypotension, **or** if it
interpolates a dropout, **or** if an awareness model is trained on BIS as
if it were recall, **or** if the full system does not beat raw-rate-only
on a pinned over-sedation hold-out by a pre-registered margin (margin
**unmeasured** until Phase 3).

## §7 Risks

| Risk | Type | Mitigation or acceptance |
| --- | --- | --- |
| License conflict (CC BY vs CC BY-NC-SA + DUA) | Legal | Synthetic samples. Do not commit VitalDB bytes. |
| BIS treated as awareness | Scientific | Memo, CLI, and every payload say it is a proxy. Pivot to over-sedation. |
| Flush learned as hypotension | Technical | SQI is a hard gate. `artifact` is the teaching case. |
| 2-compartment reduction vs full Schnider | Technical | Cited. Phase 2 can restore V3/CL3 if Ce error vs 3-cmt is large (**unmeasured**). |
| Users read output as a monitor | Legal | Disclaimer on CLI, API, README. Not a device. |
| Awareness too rare to model | Data | Measured as the pivot in §4.2. |

### Highest-risk technical unknowns going into Phase 1

1. Whether a real VitalDB arterial-line flush has the same square-jump
   signature the rule uses (unmeasured on real bytes).
2. Whether enough cases have simultaneous infusion-rate and BIS tracks for
   a Phase 3 Ce-vs-proxy table.
3. Whether restoring Schnider V3/CL3 changes bolus-peak timing enough to
   matter for over-sedation windows.
